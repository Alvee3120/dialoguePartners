# Taste
- Prefers building websites with Next.js when a project is frontend-only. Confidence: 0.9
- Prefers starting with a basic design first and improving/refining the design in later iterations, rather than polishing in the first pass. Confidence: 0.9
- Prefers incremental, review-gated delivery: build one part/section, hand it over for the user to check, and only continue when the user approves — never the whole site at once. Confidence: 0.9
- Prefers image placeholders that visibly state which image goes where (path, subject, crop) over sourcing or embedding real photos. Confidence: 0.9
- Prefers to supply site content piece-by-piece in later messages; build pages from that provided copy rather than inventing content. Confidence: 0.8
- When the user provides a detailed, structured content specification (numbered sections covering every page with headings, eyebrow labels, body copy, CTAs, form fields, and contact details), expects that provided copy to be implemented faithfully and verbatim across all routes/data — including carrying the exact eyebrow labels, section headlines, intro lines, and CTA buttons into the components — rather than paraphrasing or restructuring. Confidence: 0.8
- For unspecified fields in a content spec (e.g. advisor roles, focus areas, bios not provided by the user), is comfortable with the agent drafting reasonable placeholder copy and clearly flagging it as an adjustable draft for later confirmation. Confidence: 0.7
- When supplying exact copy, wants it reproduced byte-for-byte and does NOT want it "polished": no grammar fixes, no title-casing/headings changes, no wording tweaks — even when the original contains grammatical errors or lowercase sentence starts (responds to such edits with just "exact"). Any suggestions about corrections should be raised as optional notes, not applied. Confidence: 0.9
- Expects a full multi-page architecture from the start (home = overview linking out → dedicated About, Insights with per-pillar detail pages, People with individual profiles, Contact), not a single-page landing — even when the brief only names "home page sections." Confidence: 0.9
- When content areas are described as "others will be added by you," expects the agent to proactively scaffold those pages/routes with placeholder content in the current iteration rather than deferring them until asked. Confidence: 0.8
- When asked to replicate a reference design image, expects the layout, spacing, colors, and typography to match the reference exactly ("follow the exact same design", "make sure the design and colour exactly look the same"), not just loosely resemble it. Confidence: 0.9
- When a reference design/theme conflicts with the project's own branding/content, prefers to match the reference's look and structure but keep the project's own branding and copy in those slots ("match look, keep our content"), rather than reproducing the reference's text/content verbatim. Confidence: 0.9
- For images that will be supplied later, prefers clean neutral gray placeholder boxes that are easy to swap for real assets over stylized mockups that mimic the reference's imagery. Confidence: 0.9
- Prefers replacing static placeholder images with real media (e.g. background video) in hero sections, using autoplay + loop + muted + playsInline with no controls, layered under a dark semi-transparent overlay (plus a vertical gradient) to keep text legible. Confidence: 0.8
- Prefers the overlay/scrim over background hero media to be light enough that the underlying video/image stays clearly visible — asks to lower the overlay opacity ("make the video more visible") rather than keeping heavy dark tints for text contrast, and for section background images is happy to drop the white overlay/gradient entirely ("no need to use the bg overlay"), expecting the overlay div and all its CSS rules (base, desktop, mobile) removed rather than just toned down. Confidence: 0.55
- Hosts site assets (images, video) on R2 and supplies them as remote URLs (e.g. hero video, footer background image); once provided, expects them wired into the site data (e.g. a `site` data constant) and rendered with Next.js Image (configuring `remotePatterns` in next.config for the R2 host) rather than keeping placeholder slots or local copies. Confidence: 0.85
- When asked to "use the related img" for sections but has not yet provided real photos, prefers the agent to actually source theme-matched stock images from the internet and wire them into each section now (rather than leaving gray placeholder boxes) — treating them as temporary stand-ins the user will swap out later. Confidence: 0.8
- When sourcing stock images for sections, cares that each image genuinely matches its section's subject ("related"); expects the agent to verify the actual content of an image before wiring it in rather than trusting a guessed URL/filename, and to self-host the downloaded files in the project (`public/images/`) so the site no longer depends on the third-party host. Confidence: 0.8
- Prefers detail/profile pages to be built "in details" and "more graphical" — rich multi-section layouts with icon-backed competency cards, timeline, numbered highlight lists, and photo galleries — over minimal/simple layouts. Confidence: 0.8
- When building a person's profile page, wants a substantial number of image placeholders (explicitly ~10+) set up for real photos the user will drop in later, rather than just one portrait slot. Confidence: 0.9
- Dislikes fabricated filler text in the UI: when real captions/descriptions aren't available, prefers them omitted entirely (render the caption only when a real description exists) rather than displaying generated placeholders like "Name — photo 01". Confidence: 0.7
- Prefers media/press sections (e.g. a profile's "Media & Interviews") rendered as image-card grids — each card pairing a photo thumbnail with a title and a link — rather than plain text link rows. Confidence: 0.6
- For server/infrastructure changes, wants nothing executed before explicit approval: asks the agent to "ask me first before executing anything" and to gate each step on confirmation rather than acting autonomously. Confidence: 0.9
- Cares strongly about not disrupting existing systems when working on shared infrastructure (e.g. hosting a new site on a server that already runs another live site): expects changes scoped to the new app only — no edits to existing configs/services — and a verification that the pre-existing site stays healthy. Confidence: 0.9
- When doing deployment/server setup, prefers being walked through it step by step with exact commands and explanations, rather than the agent completing everything on its own. Confidence: 0.8
- For hosting, prefers to deploy early to a managed platform (e.g. Vercel) to get a quickly shareable/reviewable URL first, and migrate to their own server only after the project is complete. Confidence: 0.6
- Wants the site header/nav bar to sit *on* the hero section (overlapping full-bleed hero) rather than in the page flow above it — the transparent-header-over-hero look, not a bar that pushes the hero down. Confidence: 0.75
- Wants the hero section to span the full viewport height ("100 vh") rather than a fixed pixel min-height. Confidence: 0.6
- Prefers replacing copy/prose-heavy content sections with graphical, visual content (e.g. diagrams with connected nodes, icon-backed cards) — repeatedly asks for "graphical things" / "more graphical" over walls of text. Confidence: 0.6
- Prefers full-width layout over side-by-side splits for media/content sections: media/image blocks that replace full sections should span the full width of the page container (not a narrower centered max-width), and when a section has a side image he asks to drop the two-column split — make the copy span the full container width and place the image full-width below the content instead of beside it. Confidence: 0.65
- Dislikes unused empty space beside section content — flags sections where text/headings are constrained by a max-width (`max-w-3xl`, `max-w-2xl`) as leaving too much room on the right side, and expects those constraints removed so copy spans the full container width. Confidence: 0.7
- When asking the agent to describe/explain something (e.g. "write the flow for the diagram"), wants plain content-level text describing what it depicts/means, not a technical implementation walkthrough (layout math, CSS classes, component internals). Confidence: 0.6
- When the plain-text description is requested, expects it to be substantive and informative — wants richer prose that also covers the wider company overview/positioning context (drawn from the project's existing data/content), not a terse one-line caption. Confidence: 0.6
- When adapting a reference design onto an existing page, expects only the page body to be built: the reference's global chrome (header/footer) should be skipped in favour of the project's own shared components, along with any other sections the user explicitly excludes (e.g. team members). Confidence: 0.6
- Uses the client logo's colours (Dialogue Partners) for all accent styling, with fixed hex values and role-based application: navy #173A5E as the deep accent (accent text, links, icon glyphs, focus outlines), teal #339B9E as the primary accent (buttons, highlights on dark surfaces), and light teal #DCEFEF for soft accent backgrounds (icon circles, button hovers, focus rings). Confidence: 0.85
- Does not want gold/amber accents anywhere in the palette. Confidence: 0.85
- Prefers compact icon+heading cards in feature/values grids, with the descriptive paragraph removed entirely rather than shortened (explicitly: "just keep the heading, no description"). Exception: when replicating a reference card design that clearly shows body copy under the heading, keeps/restores the descriptive paragraph (from existing data — no invented text). Also strips decorative CTA affordances from cards — asked for the circular trailing-arrow button to be removed so a card holds only image, badge, heading, and text (later edits move toward leaner cards, not richer ones). Confidence: 0.6
- Wants "dark" surfaces/sections to use the brand logo navy (#173A5E) instead of black or near-black — the brand colour should carry through backgrounds, overlays/scrims, and dark bands, not just accents. Confidence: 0.8
- Wants related cards/boxes on a page grouped so they can all be seen together at once (within a single viewport / above the fold) — prefers tightening headers, padding, and cell content to fit them in, rather than tall separated blocks that require scrolling. Confidence: 0.6
- Works from versioned, structured content briefs (labelled "v2 — Updated") supplied as the project's single source of truth: a new version supersedes the earlier draft, and expects the whole implementation to be reconciled to it — including hunting down stale hardcoded references sitewide (e.g. "four pillars" strings, counts in stats/FAQs/metadata, renamed nav labels) rather than only editing the primary data file. Confidence: 0.7
- When the agent surfaces clarifying decisions with a clear recommended default, tends to accept the recommended options as a batch rather than over-specifying. Confidence: 0.6
- When asking for a piece of content (e.g. a stats/"by the numbers" block, or an FAQ section) to be removed — even "for now" — expects it removed everywhere it appears across the whole site: a site-wide search for all renderings of the section/data, deletion of the section component and its now-orphaned data file, and cleanup of the unused imports/exports/types, rather than just deleting the visible block on one page. Confidence: 0.7
